# 파일 첨부와 작업 폴더 탐색

이 작업 폴더에 2026-09-14 TinyAgent 작업 트리의 첨부·탐색 구현을 반영하고,
첨부 출처 검사와 모델 지원 안내를 보완했습니다. 런타임과 패키지 관리자 변경은
포함하지 않습니다.

## 사용 방법

- 대화의 **+ → 이미지 및 파일**에서 **휴대폰 파일** 또는 **앱 작업 폴더**를 선택합니다.
- 휴대폰 파일은 Android 문서 선택기에서 최대 16개를 선택합니다. 앱 작업 폴더에서는
  32 MiB 이하 파일 한 개를 선택합니다. 기존 대화 UI가 이미지·PDF·텍스트를 처리합니다.
- 선택한 파일은 초안에 추가됩니다. 사용자가 전송 버튼을 눌러야 전송됩니다.
  첨부는 휴대폰 파일을 `/workspace`로 가져오는 기능과는 별개입니다.
- 첨부 선택 화면에서 이미지·PDF는 지원 모델이 필요함을 안내합니다. 현재 모델의
  능력을 자동 판정하거나 모델을 자동 변경하지 않습니다.
- 상단 **파일**에서 `/workspace`와 하위 폴더를 탐색합니다. 숨김 파일도 표시하고
  폴더부터 정렬합니다. 파일을 누르면 기존 미리보기·재생·설치·저장·공유 메뉴를 엽니다.
- 시스템 뒤로가기는 상위 폴더로 이동하고 루트에서 탐색기를 닫습니다.
  마지막으로 정상 조회한 폴더를 기억합니다.
- 터치 화면에서 첨부 삭제 버튼을 항상 표시하고 44 CSS px 터치 영역을 제공합니다.
  여러 첨부는 줄바꿈하며 트레이 내부에서 스크롤합니다.

## 취소와 경계

선택 취소·Activity 종료·다른 대화로 이동 시 첨부 콜백을 취소합니다.
현재 요청과 다른 선택기의 결과는 무시하며, 중복 파일은 한 번만 추가합니다.
`content:` URI와 선택한 출처, 파일 개수, 결과 수신 시 대화 URL을 검사합니다.
앱 작업 폴더의 공유·읽기는 기존 열린 파일 디스크립터 검증을 사용하고,
폴더 목록에는 심볼릭 링크를 표시하지 않습니다.

## 검증

```powershell
python scripts/check-attachment-results.py
python scripts/check-workspace-listing.py
.\gradlew.bat --offline --no-daemon :app:assembleDebug :app:lintDebug
python scripts/check-packaged-runtime.py
```

첨부 결과 검사는 생산 Activity 메서드를 사용하고 Android UI만 테스트 대역으로
대체합니다. 폴더 검사는 실제 임시 파일과 심볼릭 링크를 사용합니다.
Linux FD 검사는 기존 `scripts/check-workspace-files.py`에 별도로 유지합니다.

이 브랜치의 결과와 APK 경로는 [로컬 검증 기록](ATTACHMENTS-20260915.md)에 기록합니다.
9월 14일 다른 작업 트리의 Spacewar 실기기 결과는 이 APK의 실기기 검증을 대신하지 않습니다.
회전·프로세스 종료, 대용량 파일, 다른 Android/WebView 버전과 실제 모델 응답은
이 APK로 별도 확인해야 합니다.

파일 이동·이름 변경·삭제·휴대폰 파일 가져오기는 이번 범위에 포함하지 않습니다.
