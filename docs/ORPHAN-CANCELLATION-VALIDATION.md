# Persisted orphan cancellation — 2026-09-10

Pacman's previous VLC shell part remained `running` after Android killed its PRoot/backend and a new backend started. Calling `/session/{id}/abort` returned true without changing that persisted part. The current live retry is a different session and was not cancelled.

Source trace: `SessionPrompt.cancel` delegated to `SessionRunState.cancel`. When no in-memory runner existed, the latter only set the session's transient status to idle. No persisted tool record was repaired. This matches the observed restart case.

The runtime patch captures pending/running tool IDs before cancellation, invokes the existing cancellation path, then re-reads those IDs and changes only still-pending/running parts to `error` with `metadata.interrupted=true`. Input and partial output metadata are preserved. Completed parts remain unchanged. Associated unfinished assistant messages receive a completion time and MessageAbortedError; existing errors are preserved. The capture excludes tool IDs created by a later turn. Explicit cancellation currently scans retained history; a pending-part index is a future performance option, not part of this patch.

Regression in the actual OpenCode session-store fixture seeded a running shell part with no live runner. Before: expected error, received running. After: interrupted error with retained input/output, unchanged completed sibling, and finalized assistant.

## Native execution identity and startup cleanup implementation

The launcher previously recorded only a reusable PID. It now atomically records PID, Linux boot ID and `/proc/PID/stat` before exec. `RuntimeProcessIdentity` compares boot ID and start ticks while handling spaces/parentheses in the process name. Stop additionally checks the Android app UID before SIGQUIT. Still-live process markers are retained, and the preparation worker checks previous markers before starting another runtime. It signals only a matching previous execution, waits up to five seconds for that identity to disappear, and refuses to continue if termination is unconfirmed. PID reuse or another UID does not receive a signal. Legacy PID-only records for an existing app-UID process require explicit resolution rather than being trusted. No blocking wait was added to the UI-thread stop path.

Host identity checks passed matching execution, reboot mismatch, PID reuse, different PID, legacy record and malformed stat. On Pacman, the staged launcher ran directly with the ordinary app UID and successfully recorded real boot/start identity before `/system/bin/true`; no ADB or root was invoked by the launcher. Initial Android compile/lint caught unsupported Files.readString/Path.of APIs; corrected to readAllBytes/Paths.get. Subsequent assembleDebug and lintDebug passed. The updated native recovery code is not yet installed or validated with a surviving PRoot on a phone, and automatic persisted-session reconciliation remains pending. Installed Lyriq1 remains 292f2c8f.
