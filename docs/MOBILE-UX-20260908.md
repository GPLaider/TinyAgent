# Mobile UI revision — 2026-09-08

The user prioritized OpenCode settings before personal OpenAI OAuth testing.
This revision is a debug build, not release acceptance.

## Design and defects

Built-in Image Gen concepts: `design/mobile-concept-v1.png` and
`design/settings-concept-v1.png`. Brief: Korean Android R&D agent; readable
setup, session list, conversation and settings; white background, dark green
accent, 24 px gutters, 16 px body/control type, 48 px minimum primary controls;
no persistent sidebar on a phone. Existing Android views and OpenCode Solid UI
remain real controls. Images are design references, not rendered app screens.

Observed before modification in the in-app browser at 390 × 844: settings kept
a 144 px sidebar plus 40 px padding on both sides of the detail pane. Korean
descriptions wrapped into a narrow column. Native setup mixed explanatory text,
diagnostics, runtime actions and navigation at equal prominence.

Changes:

- Native setup groups root permission, environment preparation and conversation
  entry. Port settings and diagnostic output expand separately. Conversation
  entry performs self verification and backend health checks in one action.
- Phone settings use a full-screen menu followed by one full-width pane. Desktop
  retains its existing tabs. General, providers, models, servers and shortcuts
  retain their existing controllers and persistence.
- Select fields and provider actions use full-width controls. Switches align
  beside their descriptions. Model names wrap instead of being crushed beside
  a permanent sidebar. Custom provider model/header fields stack on phones.
- Provider connection and custom provider entry share the existing connection
  controller. The direct custom-provider shortcut previously opened a different
  legacy dialog; it now follows the same UI and returns to provider settings.
- Android Back first dismisses the keyboard, then follows the visible settings
  or provider back/close control, then browser history. The one-way JavaScript
  event exposes no native interface or credentials.
- Settings entry is fixed at the top of the mobile session home. A real-device
  test reproduced the old footer buttons being clipped outside the WebView;
  their accessibility nodes had zero height at y=2281.
- The native root consumes system/IME insets after applying them, preventing
  child WebView from applying the same padding again.

## GUI packaging

`patches/opencode-mobile-ux.patch` is the complete patch against official
OpenCode `v1.18.29`, commit `16747470f976aca3d362ad730bcd3fe82ecc2c9a`.
It includes and supersedes `opencode-mobile-home-scroll.patch`; do not apply
both. Upstream copyright and license notices still apply.

The built GUI is packaged in the APK. `EmbeddedWebUi` serves only manifest-listed
assets on the existing loopback origin. API requests still reach OpenCode on the
phone, using its existing authentication and sessions. There is no host proxy,
remote execution backend, JavaScript credential store or second session database.
The Linux ARM64 backend and Fedora archives retain their original pinned hashes.

`stage-web-ui.py` records each GUI asset hash and an HTML script hash based CSP.
`check-packaged-runtime.py` verifies all GUI files and both compressed runtime
archives inside the final APK. Windows public-asset symlinks are explicitly
resolved when staging. Generated assets are ignored by Git and reproducible.

Build on this Windows host, after applying the combined patch and installing the
documented upstream Bun dependencies:

```powershell
$env:PATH = 'D:/TinyAgent-work/tools;' + $env:PATH
Set-Location D:/TinyAgent-work/upstream/opencode/packages/app
```
